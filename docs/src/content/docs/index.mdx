## What Bifrost does

Bifrost runs on a Linux host in your home network. It watches the IPv6 prefix on that host. It creates service addresses, updates DNS records, and checks the inbound path.

Bifrost supports three service modes:

- `direct` publishes an IPv6 address that the backend owns.
- `splice` accepts IPv6 and opens a new TCP connection to the backend.
- `auto` uses direct mode only when all direct-mode checks pass.

An optional edge accepts IPv4 traffic on a public server. The edge sends that traffic to the home service through IPv6. Native IPv6 traffic does not pass through the edge.

## Requirements

The home role requires these items:

- A Linux host
- A global IPv6 `/64` on that host
- Permission to add IPv6 addresses
- Permission to bind the public TCP ports
- An inbound rule on the home router
- Supported DNS provider credentials

Bifrost cannot open the firewall on an ISP router. Bifrost cannot create an IPv6 path when the ISP does not provide one.

## Product limits

Bifrost supports TCP in v1. Splice services terminate TLS by default, with certificates issued automatically through the configured DNS provider. Direct services and `tls: off` pass raw TCP through. Bifrost does not add user authentication. It does not proxy UDP or QUIC. It does not change application configuration.

Bifrost is not a VPN. Bifrost is not a hole-punching system. Clients do not need Bifrost software.
